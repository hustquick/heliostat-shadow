# 指定时间和实时效率分析

四端使用相同的 `viewer/analysis.js` 界面、Open-Meteo 适配器和 Rust `analysis::instant` 内核。分析控制位于编号 04 卡片（03 阴影与遮挡来源之后），实时控制在前、指定时间在后。结果复用 01 三维、02 投影、03 来源，不在控制卡片重复显示。两种分析及逐时播放均展开 01，并聚焦顶部的只读结果时间与气象摘要，后续刷新不抢焦点。指定时间按电厂时区解释，支持秒级任意时刻（1900–2100），无需该时刻在历史数据集中存在。用户填写 DNI、气温和气压。夏令时不存在或重复的当地时刻会拒绝，避免静默计算另一个时刻。分析返回逐镜光学效率、全场反射面积加权效率、各因子平均值和跟踪工况接收光学功率，同时同步三维、二维和着色。功率是光学模型结果，不是电厂发电功率；用户启停参数单独保存，分析不修改镜场、设置或历史气象。

实时模式在每轮开始时读取设备当前时间，以当前电厂经纬度通过 HTTPS 查询 Open-Meteo。使用 `direct_normal_irradiance_instant`、`temperature_2m` 和 `surface_pressure` 的 15 分钟序列，选取不晚于设备时间的最近样本。数据为近实时模型，非测站实测；部分地区的 15 分钟序列由小时数据插值。来源说明见 [Open-Meteo 文档](https://open-meteo.com/en/docs)。数据缓存 5 分钟，最大样本年龄 30 分钟；切换地点不复用缓存。网络失败、样本缺失、单位异常和过期时明确报错并保留上次结果标注为旧结果，不以历史天气冒充实时天气。

任务串行、不排队追赶。两次开始之间的周期为严格大于本轮耗时的下一个 5 秒整数倍，仅在本轮完成后安排下一轮。例如耗时 0.5 秒，周期为 5 秒；耗时 90 秒，等待 5 秒再开始，周期为 95 秒；慢失败同样延长重试周期。耗时用单调时钟测量，分析时刻用设备时钟。停止或切换镜场后不应用迟到结果；原生计算不能强行中断，会等待其自然结束，再允许下一任务。页面进入后台会停止，需要用户重新启动实时分析。Android 使用异步原生回调和单工作线程，iOS 将分析 C API 放到后台，保持 WebView 可操作。Android 新增联网权限，不添加应用内更新入口。
